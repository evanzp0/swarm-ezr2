# EZR Downloader — TUI 界面 Demo

> **EZR 下载器**是一款基于终端用户界面（TUI）的高性能多协议下载器。
> 本仓库是**界面 Demo**：全部下载任务为伪造数据（本地模拟器驱动），
> 用于验证布局、状态流转、配色与交互体验，不含真实下载逻辑。

## 演示的状态机（全部伪造数据）

页签口径：**正在下载** = 等待中 / 下载中 / 已暂停 / 校验中 / 后期处理中 / 已失败；
**已完成** = 已完成 / 做种中。

> 不存在「连接中」状态：任务从「等待中」直接进入「下载中」；
> 已失败任务重试（自动/手动）时先回到「等待中」队列，再断点续传。

### 下载槽位队列（写死 5 个）

「任务队列」栏右侧实时显示**下载槽位 5/5**。同时可下载的任务数固定 **5** 个：

- **占用槽位**：「下载中」任务；「已失败」但**未达最大重试上限**（将自动重试）的任务
  也**继续占用**槽位。
- **释放槽位**：下载完成（转入校验）、手动暂停、达到最大重试上限停止自动重试、删除任务。
- **排队规则**：「等待中」任务按**列表顺序（从上往下）**依次获得空出的槽位后开始下载
  （列表行显示「排队第 N 位」，`U`/`J` 调整任务位置即可调整排队优先级）；
  「等待中」任务按 `Space` 会**暂停并退出等待队列**；槽位已满时对已暂停任务按 `Space`
  继续会提示「无空闲下载槽位」并进入等待队列。
- **重试计数**：按**连续性规则**更新——**连续失败**（自上次失败后未下载到任何数据）→ 计数**累加**
  （如 2/5 → 3/5）；**非连续失败**（重试期间有下载进展）→ 计数**重置为 1**；达到上限（5/5）后
  停止自动重试并释放槽位（列表行显示「已达上限」），按 `R` 手动重试会把计数重置为 1 并重新排队。
  演示任务 win11：首次失败后的重试会正常下载一段（有进展 → 展示「重置」），
  之后的重试模拟连接卡死（速度 0、无进展 → 展示「累加」直至达上限）。
- **失败分类与退避（状态切换规则对齐 mission/M1.md）**：失败按类别决定后续流转，
  详情「失败原因」行如实展示（附 HTTP 状态码）：
  - **自动重试类**（网络错误 / HTTP 408·429·5xx / 文件大小不符）：按**指数退避**
    8s → 16s → 32s → 60s 封顶倒计时自动重试；响应带 `Retry-After`（≤60s）时优先采用；
  - **不自动重试类**（语义性 HTTP 4xx / 磁盘空间不足 / SHA-256 校验失败）：直接停等
    （列表行显示「不自动重试」），仅可按 `R` 手动重试；
  - **磁盘空间预检**：获得槽位开始/续传前检查保存目录可用空间，不足则置为失败
    （不自动重试；演示任务 tensorflow 首次获槽时预检失败，按 `R` 后预检通过进入下载）；
  - **校验失败**：按 `R` 时**清除断点、从头重新下载**（数据损坏时断点无意义；
    演示任务 gpt4all 首次校验失败）；
  - **续传一致性失效**（服务器内容已更新）：断点作废、清零进度、从头重新下载。
- **文件名规则**：添加任务与既有任务重名时自动追加序号 `.1` / `.2` …（不覆盖既有条目）；
  URL 无法推导文件名时回退为 `download-<时间戳>`。

| 状态 | 徽标 | 颜色 | Demo 行为 |
|---|---|---|---|
| 等待中 | `[等待中]` | 黄 | 等待空闲下载槽位，按列表顺序排队（显示排队位次）；失败重试也回到此状态（3s 后开始）；按 `Space` 暂停并退出等待队列 |
| 下载中 | `[下载中]` | 淡蓝 | 速度抖动、分块推进，满 100% 转校验 |
| 已暂停 | `[已暂停]` | 白 | 断点已保存，释放槽位；Space 有空闲槽位时从断点恢复，槽位满则进入等待队列 |
| 校验中 | `[校验中]` | 淡蓝 | 按任务校验码模拟校验 2.6s → 已完成/后期处理（不占槽位）；校验失败 → 已失败（不自动重试，按 R 清断点从头下载）；未提供校验码的任务完成后直接跳过校验 |
| 后期处理中 | `[后期处理中]` | 淡蓝 | 压缩包解包等处理 3.4s → 已完成 |
| 已失败 | `[已失败]` | 红 | 自动重试类（网络错误 / 408·429·5xx / 大小不符）：倒计时按指数退避 8→16→32→60s 自动重试（Retry-After ≤60s 优先）且继续占用槽位（计数按连续性规则）；不自动重试类（语义性 4xx / 磁盘空间不足 / 校验失败）：行内显示「不自动重试」，仅 R 手动重试；已达上限：行内显示「已达上限」、释放槽位 |
| 已完成 | `[已完成]` | 绿 | 显示校验情况（无校验 / 按算法显示「MD5/SHA-1/… 校验成功」）与文件大小 |
| 做种中 | `[做种中]` | 粉 | BT：上传速度/种子与节点数/剩余做种时间 |

**颜色规范**（进度条填充 + 百分比/徽标文字）：已暂停=白色、等待=黄色、
下载/校验/后期处理=淡蓝色、已失败=红色、已完成=绿色、做种中=粉色。
协议徽标 `[HTTP]` / `[HTTPS]` / `[BT]` 统一用**黄色**显示。

**列表进度条**为整体进度（不分块）；分块下载情况在**任务详情**中以文字呈现：

- **分块行**：`x/y · N/块`——x = 已完成分块数，y = 总分块数，N = 每块大小。
- **分块策略（AIR2）：块大小按协议写死、与并发数解耦**——HTTP 1 MB/块、BT 256 KB/块，
  总块数 y = ⌈文件大小 / 块大小⌉（末块不足整块时吸收余数）；各连接从块队列动态领块，
  完成一块立即领取下一块（乱序完成），实际并发 = min(最大并发, 剩余未完成块数)，
  队列临近结束时连接自然转入待命。
- **并发分块明细**表格：显示各连接当前持有块号（块 k/y）；含进度/速度/状态
  （传输中 / 挂起 / 完成 / 待命）。

**任务详情**字段：状态 / 排队（仅等待中：排队位次与槽位占用）/ ID / 类型（黄色，含并发数与
断点续传支持）/ 校验（提供校验码的任务：算法 · 校验码前缀 · 状态）/ 大小 / 失败原因（仅已失败）/
速度（HTTP：↓速度+剩余；BT：↓↑速度+剩余）/ 保存路径 / URL / 分块（x/y · N/块）。

**添加 / 删除对话框**：`A` 弹出「添加下载任务」对话框，5 个字段——URL、保存目录、
并发数（默认最大并发 HTTP 4 / BT 20，可修改 1–64）、**校验算法（下拉选择）**、
**校验码（可选）**；槽位已满时新任务自动进入等待队列；Tab 切换字段、Enter 确认、Esc 取消、
支持鼠标点按钮。校验算法支持 **MD5 / SHA-1 / SHA-224 / SHA-256 / SHA-384 / SHA-512 / Adler-32**
共 7 种：字段聚焦时按 `Enter`/`Space`（或鼠标点击字段）展开下拉列表，`↑↓`/`Home`/`End`
选择（选中算法后校验码占位提示同步显示期望位数），`Enter` 确认、`Esc` 关闭列表、
点击选项直接选中；校验码仅接受十六进制字符，确认时校验「纯十六进制 + 长度与算法匹配」
（如 SHA-256 需 64 位），不符合则以 toast 报错并回跳校验码字段；留空 = 不校验。
提供校验码的任务在完成后进入「校验中」，详情新增「校验」行（算法 · 校验码前缀 ·
已通过/未通过/校验中/待校验），列表完成行显示「{算法} 校验成功」。
`D` 弹出三选对话框：仅删除任务 / 删除任务和文件 / 取消。

## 运行

```sh
# 方式一：从源码运行（需要 Rust 1.85+）
cargo run --release

# 方式二：直接运行仓库内预编译的 Linux x86_64 二进制
./bin/ezr-tui-demo
```

> 需要真终端（TTY）运行。建议 120×34 及以上以获得完整信息显示；
> 支持鼠标需终端开启 SGR 鼠标协议（主流终端默认支持）。

## 快捷键

| 按键 | 作用 |
|---|---|
| `↑` `↓` | 选择任务（`Home`/`End`/`PgUp`/`PgDn` 快速跳转） |
| `Space` | 暂停 / 继续（断点续传；继续需空闲槽位，槽位满时进入等待队列）；「等待中」任务按 Space 暂停并退出等待队列 |
| `R` | 重试失败任务（从断点恢复；校验失败的任务清除断点、从头下载；重新排队后计数重置为 1） |
| `A` | 弹出「添加下载任务」对话框（URL + 保存目录 + 并发数 + 校验算法下拉 + 校验码） |
| `D` | 弹出「删除任务」对话框（仅任务 / 任务和文件 / 取消） |
| `U` | 将选中任务上移一位（同时提高槽位排队优先级） |
| `J` | 将选中任务下移一位（同时降低槽位排队优先级） |
| `C` | 清理已完成任务 |
| `Tab` / `BackTab` | 切换页签：正在下载 / 已完成 |
| `G` | 显示 / 隐藏右侧速度图表面板 |
| `Q` / `Esc` / `Ctrl+C` | 退出 |

**鼠标**：左键点击选中任务；滚轮滚动列表；对话框内可直接点击按钮。

## 架构要点（正式版将沿用）

- **异步运行时**：tokio；`tokio::select!` 同时驱动 crossterm 事件流（`event-stream`）与 100ms 渲染 tick。
- **状态与视图分离**：`app.rs` 只管状态与状态机，`ui.rs` 只管渲染；ui 层回填列表/字段行/
  下拉选项/对话框按钮命中区域给鼠标事件用（校验算法下拉框 = 浮层列表 + 选项命中区域，
  点外部收起、点击选项直接选中）。
- **校验码（可选）**：添加对话框 7 种算法（MD5/SHA-1/SHA-224/SHA-256/SHA-384/SHA-512/Adler-32）；
  提供校验码的任务完成后进入「校验中」再完成，未提供的直接完成（无校验）；
  确认时校验纯十六进制与长度（按算法期望位数）。
- **AIR2 分块队列（HTTP + BT 同模型）**：块大小按协议写死（HTTP 1 MB / BT 256 KB）、
  与并发数解耦；`Connection` 即“当前持有块”的租约，完成即领下一块（乱序完成），
  这正是断点续传与多并发的数据基础。
  列表进度条显示整体进度，详情页以文字（x/y · N/块）与块号明细呈现分块状态。
- **失败重试语义（M1 规则口径）**：失败分类 `FailKind`（Transient / Fatal / Verify /
  Invalidated）决定自动重试行为——可重试类按指数退避 8→16→32→60s 倒计时（`Retry-After`
  ≤60s 优先）；语义性 4xx / 磁盘预检失败 / 校验失败停等、仅可手动重试；重试（自动/手动）
  先进入「等待中」队列再断点续传（无「连接中」状态）；失败原因展示在任务详情（附状态码）。
- **下载槽位调度**：写死 5 槽位（`MAX_DOWNLOAD_SLOTS`），每 tick 开头先回收/分配：
  下载中与待自动重试的已失败任务恒持有槽位（`Task::has_slot`），空闲槽位按列表顺序
  （从上往下）分配给最靠前的「等待中」任务——调度器 `enforce_slots()` 为唯一分配点，
  释放点集中在下载完成/暂停/达重试上限/删除四处。
- **颜色输出**：启动时 `force_color_output(true)` 无视 `NO_COLOR` 环境变量——本界面语义
  完全依赖配色（状态色/黄色协议徽标），而 CI/沙箱环境常设 NO_COLOR=1。
- **CJK 宽度对齐**：自实现显示宽度计算与填充（`w()` / `pad_left()` / `pad_right()`），
  修复 Rust `format!` 按字符数填充导致 CJK 列错位的问题。
- **浮层翻转全量重绘**：对话框/下拉浮层出现或消失的那一帧先 `terminal.clear()` 清屏再
  全量重绘（`main.rs` 覆盖层签名检测）。浮层边框可能恰好落在底层 CJK 宽字符的右半格上，
  增量 diff 只输出单个单元格补丁，部分终端无法正确处理"覆盖宽字符半格"，宽字会残留在
  浮层边框之上（如列表"等待空闲下载槽位"盖住对话框左侧框线）且被后续帧固化；
  清屏后从零连续渲染，游标推进与网格位置严格同步，根治该残影。
- **崩溃安全**：panic hook 中恢复终端状态，异常退出不留"花屏终端"。
