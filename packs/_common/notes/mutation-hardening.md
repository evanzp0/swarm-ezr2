# 变异加固策略（语言无关）

> 用途分类：变异加固（mutation testing）工作的通用策略与陷阱，**不绑定任何语言与
> 具体工具**——换语言、换同类工具同样适用。吸收合并原 `hardening.md`（案例性叙述
> 已剔除，只留策略、问题与解法；模式库随复盘开放增长）。
> 引用本文件的角色：six-pack/hardender、squad/hardener。
> 通用工程与验证纪律见 `packs/_common/engineering.md`。

## 0. 会话隔离三原则

1. **运行时状态与产品树隔离**：变异会话数据库、配置文件、runner 脚本、scratch 树、
   运行器适配器一律放 `.work/tmp/`；产品目录只保留产品内容与测试。会话运行时产物
   不进交接与归档，交接时写明复现方法。
   **优先采用 worker 副本隔离（真实树零接触）**：为每个并发 worker 提供产品树的独立
   副本，变异与测试全部在副本上进行，相对路径按 worker 工作目录解析；并发用唯一前缀
   （如进程号）隔离副目录，路径约定经注入的环境变量传递；适配器与 runner 脚本内路径
   一律绝对路径或显式 cd 到约定根目录（防 cwd 漂移把中间产物落到非预期位置）。相比
   "原地突变 + 还原"，它把中断残留风险降为零；pristine 备份与逐文件 cmp 仍保留，
   作为收尾零改动证明。
2. **选型否决权**：凡强制在产品根写入配置文件、或在导入/启动期加载配置导致工具自身
   不可用的框架，直接弃用，另选"配置与状态可完全隔离"的工具。
   **否决前先试工作副本解法**：否决的判断对象是真实树而非工作副本——工具若只要求在
   "工作树根"有配置文件，把配置写进 worker 副本根（副本整体位于 `.work/tmp/` 下、
   随会话生灭）即视为已隔离，不必弃用；只有配置必须落在真实树、或全局/导入期读取
   而无法用副本满足时，才动用否决权。
3. **环境自重建**：会话的工具缓存与运行时笔记不进工作区产物、不随会话流转，每个会话按
   engineering.md 自行重建工具链，并把选型理由写进 `project/handoff.md`。安装前核对
   包确属目标工具——同名包陷阱真实存在（同名包可能实为无关功能的库）。

## 1. 基线先行

- 任何变异开工前，先跑全套既有验证（架构检查 / 单元 / 验收 / 属性）并核对与上游
  交接说明（`project/handoff.md`）记录的数字一致；基线不绿不开工。
- **基线与实验同语境**：对照基线必须在与变异运行完全相同的语境下取得——同一组注入的
  环境变量（手跑基线也要带全）；语境不一致的基线是无效对照（engineering.md「验证」
  同语境条款的加固现场）。
- 属性测试按 engineering.md 保持独立显式命令，不并入变异与 CRAP 的被测命令。

## 2. 变异执行策略

- **分轮收敛**：首轮用小清单画像（校准 runner、基线与清单口径），发现工具或流程缺陷
  先修复再放量；每轮之间复盘假阳性与残留问题，末轮全量收官。不要在一轮里赌完全部
  突变体。
- **大分类先根因归类，再逐个处置**：每轮结果先按 killed / no_tests / survived /
  timeout / suspicious 把根因三分——工具缺陷、覆盖缺口、等价类——而不是逐个硬看。
  **整模块级 no_tests 批量类**（同一模块全部位点同报 no_tests）通常不是工具故障，
  而是"该模块无直接测试覆盖"的正确信号：按 §4 检查器加固处置，处置落地后该类应整体
  消失——整体消失本身就是解读正确的验证。同理，timeout / suspicious 批量集中时先查
  runner 语境，幸存集中时先查等价。
- **known-answer 校准与作废重建**：放量前先用已知答案探针校准验证入口——注入一个
  必然被杀灭的突变体（或临时弄坏一条测试），确认入口如实报杀/报红后再采信其批量判定；
  看不见蓄意失败的验证入口会批量制造假存活。修复工具或流程缺陷后，缺陷期间产出的全部
  判定作废：删除会话状态整体重建重跑，以连续两轮计数收敛为准，不在旧结果上打补丁。
- **pristine 备份**：变异开始前对产品源码做字节级备份（`.work/tmp/pristine/`）。
  "原地突变 + 还原"模型的工具可能因进程中断残留突变体，污染后续判定——每个执行窗口
  结束后与 pristine 逐文件 cmp/diff 核对，收尾时整体核对一次；发现残留即用备份逐窗
  还原并整体重跑修正。
- **清单制差分变异**：用手写源清单（人工审核，按会话目的决定生成代码的去留——
  验收模块变异可排除生成代码，检查器变异则需同构 scratch，见下）；不使用全量变异
  开关。
- **test-command 执行语义陷阱**：多数变异框架不经 shell 执行测试命令（按 argv 切分），
  `&&`、重定向等 shell 语法会变成位置参数导致 baseline 失败——把多套件验证包进
  **单一 runner 脚本**（放 `.work/tmp/`），配置里只引用该脚本绝对路径。
  **runner 必须聚合退出码**：串联多套件命令的 runner 若不显式聚合（任一段失败即整体
  失败，收尾统一返回失败码），退出码只反映最后一段，前序套件的失败会被静默掩盖，
  同样制造批量假存活/假绿。
- **会话续跑与失效**：优先利用 exec 类断点续跑能力（天然跳过已完成突变体）；
  改动测试后无增量 reset 就删除会话状态整体重建。
- **并发**：工具支持 worker 时用多 worker（角色条款给出上限则以上限为准）；工具本身
  无并发能力时可**自建进程级并行**——按 §0 的 worker 副本隔离，为每个 worker 建立
  产品树独立副本与独立工具会话，各会话以互斥的源码清单圈定范围并行推进，收尾逐文件
  cmp 出零残留证明；选择顺序执行并在 `project/handoff.md` 如实记录受限说明同样可接受
  ——这是如实记录，不是违规。
- **长运行可见性**：始终开启详细输出 / 进度模式，区分正常长运行与挂起。
- **scratch 树同构**：为检查器 / 规则引擎类模块做变异加固时，测试用 scratch 副本必须
  与真实树结构**完全同构**（含生成目录与空目录）——过度 ignore 会让真实扫描差异漏检
  （如忽略生成目录导致其中变异存活漏网）。

## 3. 存活突变体处理（零存活目标）

- **先排除假阳性**：复盘存活清单时先怀疑度量工具本身——对可疑存活体先复核工具的
  路径假设与运行语境（如误用 pristine 副本当扫描目标会把"突变未生效"误判成"存活"），
  确认是真存活再进入杀灭/等价论证流程。
- 每个存活突变体二选一：**被新加固测试杀灭**，或**写成书面等价论证**；非等价存活率
  必须为 0，总杀灭率如实报告。
- 等价论证按以下**高频模式**归类比逐个硬想更快；模式库随每轮复盘开放增长——装不进
  既有模式的新等价类，应沉淀为新模式并写明失效条件：
  1. **卫语句先行**：上游守卫已把值域限定，后续比较的算子替换在一切可达上下文恒同值；
  2. **入口卫比较**：入口卫在脚本态 / 导入态下两种比较方向恒同；
  3. **驻留 / 规范化同一性**：经驻留或规范化的值上，同一性判断与相等判断等价
     （须标注实现相关性）；
  4. **固定集合排序**：元素集固定且恒在比较枢轴单侧，序关系不翻转任何真值；
  5. **死分支**：当前语料不可达的分支（如零相对导入）；
  6. **别名归一**：被变异的字面量是同一逻辑值的别名拼写（编码名、大小写、连字符/
     分隔符变体等），运行时归一化后恒同值（失效条件：消费方改为严格匹配，或新增
     不做归一的消费方）；
  7. **环境条件分支**：两侧差异仅在特定环境/配置（locale、编码、平台、外部工具版本）
     下可观察，当前环境恒走同一侧（失效条件：环境或配置变化，或该分支被直接测试）；
  8. **falsy 等价默认 / 哨兵等价**：默认值或哨兵仅参与真值判断、或仅被同簇成员按值
     识别，替换为同真值或同簇的另一值恒等价（失效条件：出现身份或类型敏感的消费方）；
  9. **边界空转**：边界外推多出的迭代/元素对当前语料恒空转、无可观察效果
     （失效条件：语料触达新边界）。
- **等价论证必须写失效条件**：新增模块、引入新模式、更换运行时实现都会使等价类失效；
  交接时写明回补触发条件。

## 4. 加固测试写法

- **独立布局**：加固测试独立成套（如 `tests/hardening/`），与单元 / 验收套件分离，
  入口命令写入 `project/handoff.md` 供下游回归。
- **一测一靶**：一条加固测试对应一个存活体或一类等价场景；**断言精确规则集**而非
  子串包含——多违规并存可能是合法行为，只有精确集断言才防回归。
- **精确制导**：用最小合成输入建立"行号 → 行为"映射，逐算子（取模 / 移位 / 异或 /
  比较符）配最小用例，而非泛泛加断言。
- **契约断言用可观察输出**：如"输出不含转义序列"；不要用携带原始非 ASCII 字符的
  标识符当判据（会被模板原样携带而漏判）。
- **检查器类加固**：逐规则注入违规到 scratch 副本断言拒绝 + 干净树通过反
  false-positive；单次建模板、复用副本降低慢 IO 成本。
- **金样夹具用捕获脚本生成**：检查器/生成器的金样期望输出（干净运行完整 stdout、
  渲染字节契约、逐规则违规的完整输出），用一次性捕获脚本从**干净实现**自动捕获，
  不手写期望输出——手写必有笔误且难随实现维护；捕获脚本属开发期工具（放 `scripts/`
  或 `.work/tmp/`，不入测试套件），实现有意变更时重跑脚本再生金样。
- **加固套件双口径可跑**：不绑定单一测试 runner（如同时兼容两类 runner 入口，双口径
  全绿），入口命令写入 `project/handoff.md`——下游环境用哪种 runner 不可预知。
- **新增强化测试自身也要过 DRY/CRAP**：发现的样板重复先提取 helpers 再归零。

## 5. 验收 / Gherkin 变异

- 差分变异基于**已批准的 feature 清单**；未批准或无步骤处理器的 feature 不入清单。
- **运行器适配器**是项目特定的会话工具：per-job 隔离、支持并发 worker、按协议输出
  metadata；放 `.work/tmp/` 不入产品树。适配器与协议的任何语义偏差（如"同一入口点
  执行变异 IR"以重生成实现）必须在适配器内文档注明。
- 变异工具写入 feature 文件的自管理注释（stamp / manifest）属正常行为：内容未变时
  差分复用会跳过全部场景；需强制全量重跑时删除该注释块即可——交接必须写明。
- **对接文件命名可能是路径派生的**：工具的元数据/缓存文件名可能由输入路径整串 slug 化
  派生（把目录前缀也编进名字），工作目录一动即与预期名失配，关联信息静默丢失（如
  实现哈希被记为 unknown）。对接前先用最小样例核对工具的实际命名算法；需要自产其
  对接文件时按同一算法重算命名，并保证文件内的路径字段与调用参数逐字一致；交接写明
  路径敏感性与影响面（哪一级差分复用会因此失效）。
- 变异暴露 no-op 步骤时，优先从 feature 中**移除该步骤**，而不是为断言它添加示例列。

## 6. 最终验证序列与交接

- 固定序列：**语言变异 → 软 Gherkin 变异 → CRAP → DRY**；前一步发现问题先修复再进
  下一步；全绿后才写交接说明（`project/handoff.md`）。
- **产品源码零改动是默认达标线**：加固角色的产品树新增只允许加固测试与工具自管理
  注释；以 pristine 逐文件 cmp 证明。
- **交接四要素**（写进 `project/handoff.md`，缺一不可）：
  1. 本地验证命令清单（按序，含加固套件入口）；
  2. 会话运行时产物位置与复现方法（不进工作区产物，交接时写明复现方法）；
  3. feature 注释块与差分复用注意事项；
  4. 等价突变体清单及其失效条件（回补触发）。

## 7. bin-only crate 与挂载式加固的实践补充（hardender-20261004 批次沉淀）

- **挂载式加固测试的 unviable 副作用要显式披露**：以 `#[path]` 把产品模块挂进
  加固测试后，结构性变异体（改签名/删项）会使测试代码无法编译 → cargo-mutants
  判 unviable 而非 missed。unviable 不等于杀灭（产品语义未被行为测试证伪），
  汇报杀灭率时必须把 unviable 从分子中剔除并说明口径。
- **复跑测试口径必须包含全部加固目标**：runner 的 `--cargo-test-arg=--test`
  逐目标列出；漏列 = 该套件测试不参与变异判定（曾造成 bin 自带单测整批假存活）。
  bin 源含 `#![inner]` 属性时 `include!` 不可用，`#[path]` 挂载才合法。
- **临时目录按运行实例唯一化并收尾清理**：产品内部测试常用「固定前缀 + PID」
  命名 /tmp 目录；长容器内 PID 复用会让下一次运行 restore 到上一实例的注册表，
  制造批量基线假失败（同前缀 App::new 恢复出多任务/文件缺失）。变异会话启动与
  重试前清空这些前缀目录，或统一改用带时间戳/随机后缀的目录名。
- **进程级靶点用 `CARGO_BIN_EXE_<name>`**：帮助文本、退出码、监听拉起等 main
  层变异体在集成测试里用 `env!("CARGO_BIN_EXE_ezr")` + try_wait 轮询杀灭，比
  论证「不可测」更诚实；配合隔离 EZR_HOME 防读用户配置。
- **事件驱动状态机的观测窗陷阱**：单 tick 会同帧排空全部积压事件，中间态
  （如 Queued→Downloading）可能不可观测——测试设计要么让输入流持续（滴流桩
  服务器），要么断言终态/持久化产物（sidecar 落盘、改名结果）而非中间态。
  桩 HTTP 服务器必须先读完请求再响应，否则 hyper 客户端报 UnexpectedMessage。

- **位点级定向重跑（`-F/--re` 正则筛选）代替全文件重跑**：验证「新测试是否杀灭特定
  存活体」时，按变异工具 list 输出行做正则筛选只跑目标突变体（cargo-mutants 为
  `-F '<file>:<line>:<col>: replace <op>'`，`|` 交替多个位点、正则元字符转义），
  与全文件分片重跑相比时延差百倍级。配套纪律：①测试集合只增不减时，历史 caught
  位点无需重跑（不可能回退为存活），只验证残留 MISSED；②同行多算子变体会一起命中
  正则，多跑的是已 caught 位点，无害；③筛选名单先 `--list` 核对匹配数再放量。
