# 交接文件书写规则（handoff-template）

> `project/handoff.md` 是流水线内角色之间的唯一交接文件：下游角色以它为上游交接内容
> （宪法第一章「上游交接双来源」）。
> 本文件定义它的结构与书写规则，供各角色写交接时套用；制度性规则（何时写、工作区纪律）
> 以 `CONSTITUTION.md` 第三章为唯一来源，本文件只做格式细化，两者冲突时以宪法为准。

## 一、handoff.md 是什么、不是什么

- **是什么**：两节结构——「产物历史完成情况」+「当前产出情况」。它回答下游角色与操作者
  两个问题：**流水线走到哪了（累计状态）**、**本会话产出了什么（本轮增量）**。
- **不是什么**：不是经验库。开发、验收、测试的技术经验与踩坑注意事项**不得写入**
  handoff.md——它们属于项目经验，沉淀去处是工具侧 `packs/_common/`（通用纪律归
  `engineering.md`，语言/工具/框架专项归 `notes/` 目录，无合适分类文件可新建），
  由角色**在交接前直接写入**，见宪法第三章「踩坑与经验沉淀」。
- **写法基调**：每次会话**整理重写**，不是追加流水账——历史节把历次产物完成情况合并成
  一份当前有效的总账（旧会话的过程性叙述、已被覆盖的中间状态删除），当前节只描述本会话
  结束时的真实状态。文件体积因此有界，下游永远读到"当前有效口径"而不是考古地层。

## 二、文件结构（模板）

```markdown
# 交接（handoff）

> 流程：<工作流>　当前节点：<工作流>/<角色>　会话：<会话标识（角色-时间戳）>

## 一、产物历史完成情况

（流程开工以来各节点的产物累计状态，每次执行时整理重写为当前有效口径。）

### 项目与需求
- 一句话项目定位；需求权威来源（mission.md；分期模式含 mission/ 分期详述 / 上游文档）。

### 产物总账
| 节点/切片 | 产物 | 完成情况 | 验证状态 |
|---|---|---|---|
| specifier | features/ 23 份规格 + qa/ 23 份套件 | 全部交付 | parser 23/23、dry-check 0 findings |
| coder 切片1 | Rust workspace 四 crate + 验收基建 | 已交付 | 单测 104 绿、smoke 8/8 |
| coder 切片N | <本切片产物> | 已交付 | 单测 188 绿、验收 279P/0F/34S |
| … | … | … | … |

（颗粒度以"下游接手需要知道什么已完成、什么状态"为准：一个节点一行或一个功能域一行，
逐条列验证命令结果即可，不写执行过程。）

### 遗留受限项（当前有效）
- 什么没做/什么场景不可自动化/什么环境不可用——只登记**状态与影响面**，
  不写绕过手法与诊断过程（那是经验，归 packs/_common/）。

### 实现定义值登记（如规格含「由实现定义」项）
- 产品契约值唯一清单（累计维护，始终覆盖为最新全量，不逐切片追加）。

## 二、当前产出情况

（本会话产出，每次重写；上一会话的"当前"节内容已被并入第一节总账。）

### 本会话产物清单
- 新增/修改的文件与内容摘要（路径 + 一句话说明）。

### 验证证据
| 验证项 | 结果 | 命令（可复现） |
|---|---|---|
| 单元测试 | 188P / 0F | cargo test |
| 协议冒烟 | 8/8 | bash acceptance/protocol-smoke.sh |

### 对账口径（如存在基线）
- 与上游基线的增量对账（+N P/−N S 及其归属），数字必须能从分项复算自洽。

### 待办与待批（未决项）
- 需要操作者批准/澄清的问题；本会话被阻塞的事项（含已尝试路径与缺失输入）。

### 移交建议
- 建议的下一角色与理由（仅建议，不构成自动流转，宪法第一章）。
```

## 三、书写规则（逐条）

1. **整理重写，不追加**：每次会话结束时重写整个 handoff.md——把上一版的历史节与本会话
   的产出合并整理成新的历史节，再用本会话实况重写当前节。禁止按会话切片逐个追加"纪要"
   章节（那是旧 notes.md 的反模式：文件无限膨胀，下游要在十几个历史纪要里考古当前口径）。
2. **零技术经验**：不写踩坑处置、注意事项、排查手法、"供下游免踩"段落。经验类内容的
   归属：语言/工具/框架专项 → `packs/_common/notes/`（无合适文件可新建）；跨语言通则 →
   `packs/_common/engineering.md`。写入途径是角色在交接前直接写入对应文件（宪法第三章）。
3. **零过程叙述**：不写执行日志、中断经过、排查时间线、"本轮首先做了什么"。
   只写产物状态与验证结果。
4. **状态用可复现证据支撑**：验证状态一律附命令与结果数字；对账数字必须能从列出的
   分项复算自洽（engineering.md「计划的估计数字与实测不符时」条款）。
5. **受限项只登记状态与影响**：写"什么不可用/哪些场景因此跳过/影响什么口径"，
   不写诊断与绕过过程。
6. **未决项显式落盘**：待批准、待澄清、被阻塞的事项写进当前节「待办与待批」，
   答复操作者时同步列出（宪法第三章 blocked 规则）。
7. **保持简洁**：总账颗粒度到"节点/功能域"级即可；全文件以数百行为限——
   超长说明重构成表格与一句话摘要。

## 四、正例与反例（内容取舍）

| 内容 | 去处 | 示例 |
|---|---|---|
| feature f01 收口为 8P/0F/0S，全量 279P/0F/34S | ✅ handoff.md 验证证据 | 状态与数字 |
| 实现定义值：session_timeout 最小 5 秒 | ✅ handoff.md 登记表 | 产品契约 |
| 受限项：f21-dht 7 场景需本地组网 fixture，暂不可自动化 | ✅ handoff.md 遗留受限项 | 状态与影响 |
| 验证命令清单（下游回归入口） | ✅ handoff.md 验证证据列 | 可复现命令 |
| "新 shell 必须补 PATH 否则构建挂" | ❌ handoff.md → 工具侧 | notes/rust.md |
| "块首场景 socket 竞态判别三证据" | ❌ handoff.md → 工具侧 | engineering.md 测试执行纪律 |

| 中断时间线与恢复过程 | ❌ handoff.md（任何节） | 不写；plan.md 已记录勾选状态 |
| 下游建议：先跑 cleaner 收敛警告 | ✅ handoff.md 移交建议 | 给操作者的建议 |

## 五、维护责任

- **各角色**：会话收尾时按本模板重写 `project/handoff.md`（首角色建档时若上游无此文件
  则新建；上游已有则整理重写）；交接前按宪法第三章把本轮经验按归属写入
  `packs/_common/engineering.md` 或 `packs/_common/notes/` 分类文件（本模板不承载经验内容）。
- ** specifier（各工作流首角色）**：建档 mission.md 的同时初始化 handoff.md 骨架
  （历史节可只含"项目与需求"一行）。
