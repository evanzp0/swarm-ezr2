# 模块图的整洁架构（Clean Architecture）

为本主题勾勒**策略 vs 机制**——而不是 API、类或框架。
使用主题模块图（theme-module map）组织模块。依赖只能**向内**指向。

## 核心思想

**内层 = 策略。外层 = 机制。**

| 层 | 是什么 | 在图中的归属 |
|--------|------------|----------|
| **实体（Entities）** | **主要数据模型**加上**操作该数据的通用函数**——许多用例共享的核心领域事实与操作（如洞穴图 + 邻接操作、猎人 + 位置/状态操作）。最稳定；不是 UI，也不是具体 IO。 | 共享领域清单，和/或作为各用例之下的**共享领域概念** |
| **用例（Use cases）** | 将实体编排起来以达成目标的**应用特定**流程规则 | **用例（业务 / 流程规则）**——主要结构 |
| **UI 适配器** | 呈现 / 交互界面 | **UI** |
| **IO 适配器** | 文件、stdio、时钟、RNG、数据库、框架 | **IO** |

## 依赖规则

- 源码依赖只能**向内**指向。
- 用例可以依赖**实体**；用例和实体都不依赖 UI 或具体 IO。
- UI 和 IO 依赖流程（或流程拥有的端口）——绝不能反过来。
- 跨边界传递**简单数据**，而不是 UI 模型或数据库行类型。

## 你要写的内容（粗粒度）

1. **目的** —— 系统为何而建；这种分离保护的是什么。
2. **依赖规则** —— 针对本主题的"只能向内"要点。
3. **实体** —— 命名主要数据及其上的通用操作（简要）。
4. **用例** —— 每个用例：意图、流程职责、建议的流程模块、使用哪些实体、"不拥有"哪些 UI/IO。
5. **UI** —— 命令、提示、显示的状态；它们驱动哪些用例。
6. **IO** —— 外部机制；流程定义需求，IO 负责实现。

## 北极星（North star）

**实体（数据 + 通用操作）和用例在内；UI 和 IO 在外；箭头只向内指。**
