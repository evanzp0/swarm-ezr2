## 1. 项目背景与原始意图

EZR（ezr download）是一款**基于终端用户界面（TUI）的高性能多协议下载器**。

其界面与交互已通过 `ezr-tui-demo`（Rust + tokio + ratatui + crossterm，伪造数据本地模拟）
完成设计与验证：布局、任务状态机、AIR2 分块展示、5 槽位排队调度、失败重试语义、
添加/删除对话框、快捷键、配色与 CJK 对齐均已由操作者逐轮定稿（原始意图记录见
ezr-tui-demo 的 README 与历次修改记录，本大纲与各期详述保持该原始意图，不增删曲解）。

正式版项目「ezr download」的目标是：**沿用 demo 定稿的界面与交互基线，接入真实下载内核**——
先交付 HTTP/HTTPS 下载器（第一期），再扩展 BT/磁力链（第二期），最终成为日常可用的
终端下载工具（aria2 级的内核能力 + 更好的 TUI 管理体验）。

## 2. 项目目标

1. **真实可用**：在真实网络环境下完成端到端下载链路：添加 → 探测 → 并发分块下载 →
   断点续传 → 失败重试 → 完整性校验 → 完成。
2. **UI 基线不变**：界面布局、状态机、配色、快捷键、对话框与文案以 ezr-tui-demo 定稿为准，
   界面演进须经操作者确认。
3. **高性能**：多连接分块并发下载，充分利用带宽；状态与视图分离，渲染流畅不卡顿。
4. **可靠**：断点续传、崩溃/断电恢复、自动重试、完整性校验，任意时刻中断不损坏数据。
5. **轻量交付**：单二进制、无外部运行时依赖；跨平台（Linux / macOS / Windows）。

## 3. 范围

### 3.1 范围内

- 终端 TUI 下载管理器（任务列表 / 详情 / 队列调度 / 对话框 / 快捷键 / 鼠标）。
- 协议支持分期推进：HTTP/HTTPS（M1）→ BT/磁力链（M2）。
- 下载内核能力：多并发分块（AIR2）、断点续传（sidecar 元数据）、自动重试与退避、
  完整性校验（MD5 / SHA-1 / SHA-224 / SHA-256 / SHA-384 / SHA-512 / Adler-32 七种算法，
  与 ezr-tui-demo 定稿一致；CLI 校验码以 <算法>=<校验码> 显式提供算法）、限速、代理、会话持久化与崩溃恢复。
- 任务管理：添加（对话框 + CLI 参数）、暂停/继续、重试、删除、重排、清已完成。

### 3.2 范围外

- GUI / Web 界面（无计划；TUI-only）。
- 浏览器扩展 / 浏览器接管、剪贴板监听、RPC 远程控制、订阅批量导入（M3 候选）。
- 视频流协议（HLS / DASH / M3U8）、FTP / SFTP / ED2K 等其他协议。
- 账号体系、云端同步。

## 4. 约束

- **技术栈固定**：Rust（stable）+ tokio 异步运行时 + ratatui + crossterm，与 demo 一致，不得更换。
- **工程流程**：开发遵循本仓库 `CONSTITUTION.md`、`packs/_common/engineering.md` 与
  `packs/_common/notes/rust.md`（Rust 配置模板强制使用）。
- **UI 基线**：ezr-tui-demo 定稿的布局、状态机、颜色规范（暂停=白 / 等待=黄 /
  下载/校验/后期处理=淡蓝 / 失败=红 / 完成=绿 / 做种=粉，协议徽标统一黄色）、
  快捷键全集与中文文案。
- **核心参数已定案**（不随实现漂移）：
  - AIR2 分块：块大小按协议默认且与并发数解耦——HTTP 默认 1 MB/块（可配置 block_size_http）、BT 256 KB/块；
    总块数 = ⌈文件大小 / 块大小⌉（末块吸收余数）；连接动态领块、乱序完成；
  - 默认并发：HTTP 4 / BT 20，可设 1–64；
  - 全局下载槽位默认 5 个（可配置 download_slots）；等待任务按列表顺序（从上往下）依次占用。
- **交付形态**：单二进制；首发平台 Linux x86_64；终端建议 ≥120×34，80 列可用（降级布局）。
- **界面语言**：中文为主。

## 5. 验收期望

1. 每期交付**可独立验收的可用版本**：真实网络（QA 用本地 fixture 服务器模拟各类服务端行为）
   端到端可用，不依赖伪造数据。
2. 界面与交互始终与 demo 定稿基线一致；偏离基线的改动须在当期需求中显式声明并经操作者确认。
3. 质量门槛：`cargo build` / clippy 零警告；关键纯逻辑有单元测试（分块计算、状态机、
   元数据读写）；每期附端到端 QA 套件（可在本地重复执行）。
4. 交付物：源码 + 预编译二进制（Linux x86_64）+ README（含使用说明与自动化验证方式）。
