# QA 套件 · 01-add-task 任务添加（期号 01）

> 对应规格：`project/features/01-add-task.feature`（17 场景）。
> 端到端 UI 层验证：只用用户可达入口（TUI 按键/鼠标、CLI 参数、磁盘产物观察），不进入项目内部 API。

## 环境前置

- 本地 fixture 服务器：提供测试文件（含 `big-one.bin` 等）、`Content-Disposition` 头可控、重定向链可控。
- 伪终端驱动：按键注入、画面捕获、toast/对话框断言（参照 `ezr-demo/scripts/capture.py`、`verify_ezr.py` 的注入与断言方式）。
- 独立 HOME（干净 `~/.ezr`）；独立保存目录 `/tmp/qadl`（用例间清空复位）。
- fixture 校验伴随文件按用例预置/清空。

## 用例

| 用例 | 场景 | 操作（用户可达入口） | 通过判据（可观察状态） |
|---|---|---|---|
| QA-01-01 | 01-add-task-01 | `A` 打开对话框→逐字段输入五字段→`Enter` 确认 | 任务出现在列表（等待中/下载中）；详情显示类型 HTTP（v1.14 类型行无并发数）与校验 SHA-256，并发 4 经头部数据面字段「并发 4」核验（04-ui-conns-16）；目标文件落盘 `/tmp/qadl` |
| QA-01-02 | 01-add-task-02 | 算法字段 `Enter` 展开→`↓`/`Home`/`End` 选择→`Enter` 确认 | 下拉含 7 算法；选中 SHA-512 后校验码占位显示 128 位 |
| QA-01-03 | 01-add-task-03 | 输入含 `zz`/`-` 的校验码 | 逐键过滤：非十六进制字符无法输入（纯非法输入字段保持空）；确认无格式报错，空值按「无校验」创建任务 |
| QA-01-04 | 01-add-task-04 | SHA-256 配 32 位码 / MD5 配 64 位码→确认 | toast 报错位数不符（期望 64/32 位）；焦点回校验码字段 |
| QA-01-05 | 01-add-task-05 | ①校验码留空确认；②输入大写 MD5 码确认 | ①详情显示「无校验」；②校验行前缀为小写 `d869db7f` |
| QA-01-06 | 01-add-task-06 | 并发字段分别输入：留空/0/65/abc | 四种输入均建任务成功且头部数据面字段显示「并发 4」（v1.13 数据面口径） |
| QA-01-07 | 01-add-task-07 | URL 分别输入：无协议/ftp:///本地路径 | 三种输入均 toast 报错且列表不新增任务 |

| QA-01-09 | 01-add-task-09 | CD 缺失且两级 URL 末段均空 | 文件名匹配 `download-<数字时间戳>` 格式 |
| QA-01-10 | 01-add-task-10 | 预置同名文件后添加同名任务 | 新目标为 `report.pdf.1`，原文件字节未变 |
| QA-01-11 | 01-add-task-11 | 组合：配置 download_dir±留空±目录不存在 | 解析顺序=输入>配置>用户主目录下载目录；目录自动创建 |
| QA-01-12 | 01-add-task-12 | CLI：`ezr <url> -d -c -x <算法>=<校验码>`（sha256=64 位 / MD5=32 位 / adler32=8 位 各一次） | 启动成功；详情算法依次 SHA-256/MD5/Adler-32（算法由前缀显式指定，大小写不敏感） |
| QA-01-13 | 01-add-task-13 | CLI：`-x` 分别给裸校验码（无 = 前缀）/ `sha3=<hex>` / `md5=<64 位>` | 非零退出码+「-x 校验参数非法」报错；无任务创建 |
| QA-01-14 | 01-add-task-14 | CLI：`-c 0` / `-c 65` / `-c abc` | 非零退出码+并发数非法报错；无任务创建 |
