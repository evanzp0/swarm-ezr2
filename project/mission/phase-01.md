# 01 · HTTP/HTTPS 真实下载内核与 TUI 正式版（第一期详细需求）

> 期号：**01**（分期模式；需求大纲见 `../mission.md`）。
> 本文档是 01 的唯一需求详述依据：01 的 feature 与 QA 文档依本文生成，产出文件在文件名或头部标注期号 01（宪法第一章）。
> **UI 行为基线**：`ezr-tui-demo` 定稿的布局、状态机、配色、快捷键、对话框即本期 UI 规格；
> 本文只叠加「真实下载」带来的行为需求。与 demo 表现有意分歧的条目以 ☘ 标注并说明理由。

---

## 1. 期目标

把 ezr-tui-demo 的界面与状态机从本地模拟数据切换到**真实 HTTP/HTTPS 下载内核**，交付日常可用的
终端下载器 MVP：完整链路「添加 → 探测 → 分块并发下载 → 断点续传 → 失败重试 → 校验 →（自动解包）→ 完成」，
支持会话持久化与崩溃恢复；UI 与交互和 demo 定稿基线保持一致。

## 2. 本期范围

### 2.1 范围内

- 协议：HTTP/1.1 与 HTTPS（含重定向跟随）。
- 下载内核：多并发分块（AIR2）、断点续传（sidecar 元数据）、自动重试与指数退避、
  SHA-256 校验、全局限速、HTTP(S) 代理。
- TUI 全部基线功能接入真实数据（模拟器移除）。
- 会话持久化（任务注册表）与崩溃恢复。
- CLI 启动参数添加任务；单实例运行保护。
- 交付平台：Linux x86_64 预编译二进制（macOS aarch64 / Windows x86_64 保证可编译运行，P1）。

### 2.2 范围外（本期不做）

- BT / 磁力链 / 做种（分期 02；「做种中」状态仅作枚举预留，界面不出现）。
- FTP / SFTP、HLS / DASH / M3U8、ED2K 等其他协议。
- 每任务限速、限速的 TUI 控件（M3 候选；本期仅全局限速经配置/参数设置）。
- SOCKS5 代理（P2 可选）、无 TTY CLI 进度模式（P2 可选）。
- 剪贴板监听、浏览器接管、RPC 远程控制、订阅/批量导入（M3 候选）。

### 3.2 下载内核（HTTP）

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-01-10 | P0 | 任务开始时发送探测请求（携带 `Range: bytes=0-` 的 GET，或先 HEAD），获取 `Content-Length`、`Accept-Ranges`、`ETag`、`Last-Modified`；据此判定文件大小与「支持/不支持断点续传」（详情页如实显示）。 |
| FR-01-11 | P0 | **数据分块（定案，沿用 demo）**：块大小 HTTP 默认 **1 MB** （可配置）；总块数 y = ⌈文件大小 / 块大小⌉（末块不足整块吸收余数）；各连接从块队列动态领块，完成一块立即领取下一块（乱序完成）；实际并发 = min(设置并发, 剩余未完成块数)；队列临近结束时多余连接转「待命」。 |
| FR-01-12 | P0 | **不支持断点续传**（无 `Content-Length` 或服务器不响应 Range 请求）：自动降级为单并发整体下载；详情显示「不支持断点续传」；暂停后继续将从头下载（沿用 demo）。 |
| FR-01-13 | P0 | 分块写入：各块按自身偏移直接写入目标文件（并发写互不重叠）；下载中断后已下载块的字节保持有效，续传不重写已下载块。 |
| FR-01-14 | P0 | 重定向：最多跟随 10 次；以最终 URL 参与续传一致性比较（FR-01-22）。 |
| FR-01-15 | P0 | HTTPS：TLS 1.2+，使用系统根证书；证书错误按任务失败处理并在「失败原因」中展示（不提供跳过校验的开关）。 |
| FR-01-16 | P0 | 传输语义：分块下载请求禁用内容压缩（`Accept-Encoding: identity`），不得使用破坏 Range 语义的传输编码。 |
| FR-01-17 | P1 | 速度统计：任务速度与全局速度按 1 秒滑动窗口计算，驱动头部全局统计、列表信息行与 Sparkline 速度图。 |

| FR-01-21 | P0 | 断点恢复：暂停恢复、失败重试、程序重启三种路径均从 sidecar 续传；进度以 sidecar 为准合并进内存状态。 |
| FR-01-22 | P0 | 续传一致性检查：续传前比较 ETag / Last-Modified / 文件大小，任一变化或服务器不再返回这些头 → sidecar 作废、从头重下，并以 toast 告知「服务器内容已更新，已重新下载」。 |

| FR-01-24 | P0 | 正在下载的文件的文件名末尾添加 `.downloading` 扩展名，下载完成并校验成功后删除该扩展名。|
| FR-01-25 | P1 | 删除联动（D 对话框三选的落地语义，☘ 默认决定 D5）：「仅删除任务」= 只删任务记录，已下载文件与 sidecar 保留；「删除任务和文件」= 目标文件、sidecar、任务记录全部删除。 |
| FR-01-26 | P1 | 断点自动接续：重新添加与既有 sidecar 同 URL 且同保存路径的任务时，发现有效 sidecar 则自动接续断点并以 toast 提示。 |


### 3.4 状态机与槽位调度（沿用 demo 定案）

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-01-30 | P0 | 状态集（01 实际出现 7 态）：等待中（黄）/ 下载中（淡蓝）/ 已暂停（白）/ 校验中（淡蓝）/ 后期处理中（淡蓝）/ 已失败（红）/ 已完成（绿）；「做种中」为 02 预留（枚举保留、界面不出现）。**不存在「连接中」状态**：任务从「等待中」直接进入「下载中」。页签口径沿用 demo：「正在下载」= 等待/下载/暂停/校验/后期处理/失败；「已完成」= 已完成。 |
| FR-01-31 | P0 | 下载槽位默认 5 个（可配置）。占用 = 「下载中」 ∪ 「已失败」且未达重试上限（将自动重试）∪ 已获槽位的等待中任务；释放 = 转入校验（下载阶段结束即释放）、手动暂停、达重试上限、删除任务；校验中/后期处理中**不占**槽位。 |
| FR-01-32 | P0 | 排队规则：空闲槽位按**列表顺序（从上往下）**分配给最靠前的「等待中」任务；等待任务行显示「排队第 N 位 · 等待空闲下载槽位」；`U`/`J` 调整任务在列表中的位置即调整排队优先级；「任务队列」栏右侧显示「下载槽位 n/5」（满 5 时黄色加粗）。 |
| FR-01-33 | P0 | `Space` 语义（沿用 demo）：「下载中」→ 暂停（保存断点、释放槽位，支持续传任务从断点恢复）；「已暂停」→ 继续（有空闲槽位则续传，槽位满则 toast「无空闲下载槽位（5/5）」并进入等待队列）；「等待中」→ 暂停并退出等待队列（释放已获槽位）。 |
| FR-01-34 | P0 | `R` 键：对失败任务手动重试——计数重置为 1、回到等待队列、断点续传；已达上限的任务同样可按 `R` 重新排队。 |

### 3.5 失败、重试与退避

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-01-40 | P0 | 失败分类并在详情「失败原因」行与 toast 中展示：网络错误（连接失败 / 超时 / 连接被重置）、HTTP 4xx / 5xx（附状态码）、续传一致性失效（FR-01-22）、SHA-256 校验失败、文件大小不符、磁盘错误（空间不足 / 无写权限）。 |
| FR-01-41 | P0 | **重试计数连续性规则（定案，沿用 demo）**：失败发生时判定——本次尝试**有下载进展** → 计数**重置为 1**；**无进展**（如连接卡死即失败）→ 计数**累加 +1**；达到上限（配置 `max_retries`，默认 5）→ 停止自动重试、释放槽位、列表行显示「已达上限」。 |
| FR-01-42 | P0 | 自动重试与退避：未达上限的失败任务倒计时后自动重试（回「等待中」→ 断点续传）；倒计时按**指数退避** 8s → 16s → 32s → 60s 封顶，列表行实时显示倒计时（☘ demo 演示为固定 8s；退避为 demo 路线图明确要求，正式版采用）。 |
| FR-01-43 | P1 | 可重试性区分：HTTP 4xx（除 408 / 429）语义不可恢复 → 不自动重试、直接进入「已达上限」式停等（可 `R` 手动重试）；408 / 429 / 5xx / 网络错误 → 按退避自动重试；响应带 `Retry-After`（≤60s）时优先采用。 |
| FR-01-44 | P0 | 磁盘空间预检：开始/续传前检查保存目录可用空间，小于剩余需下载量 → 置为失败（原因「磁盘空间不足」），不自动重试。 |

### 3.6 完整性校验与后期处理

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-01-50 | P0 | 校验值来源（优先级从高到低）：① 添加对话框 / CLI 参数显式提供的 SHA-256；② 保存目录下同名伴随文件 `<目标文件>.sha256`（内容为十六进制摘要，或 `hex  文件名` 格式）。两者皆无 → 不做哈希校验。 |
| FR-01-51 | P0 | 校验行为：下载完成后进入「校验中」（占槽位）；有期望值 → 计算全文件 SHA-256：成功 → 「已完成」（不占槽位），列表/详情显示「校验成功」；失败 → 「已失败」（占槽位，直到重试次数到达上线才不占槽位），原因「SHA-256 校验失败」，`R` 重试时**清除该任务断点、从头重新下载**（☘ 数据损坏时断点无意义）。无期望值 → 直接「已完成」，显示「无校验」。 |
| FR-01-52 | P0 | 大小校验：实际写入字节数 ≠ `Content-Length` → 失败（原因「文件大小不符」），按重试规则处理。 |
| FR-01-53 | P1 | 后期处理（自动解包，☘ 默认决定 D3）：按扩展名识别 zip / tar / tar.gz / tgz / tar.xz / tar.zst，校验通过后自动解压到 `<保存目录>/<去扩展名>/`，期间状态「后期处理中」（不占槽位）；解压失败 → 「已失败」并注明原因；全局配置开关 `auto_extract`（默认开）；解压成功后压缩包原文件保留不删。 |
| FR-01-54 | P2 | 已完成列表展示沿用 demo：显示校验情况（无校验 / 校验成功）与文件大小。 |

| AC-1 | 对 fixture 服务器（支持 Range）以默认并发 4 下载 ≥100 MB 文件：详情显示 `x/y · 1 MB/块`、活跃连接 = 4、分块乱序完成；完成后源与目标 SHA-256 一致，状态「已完成」（无校验值时显示「无校验」）。 |
| AC-2 | 下载至 ≥30% 时 `kill -9` → 重启：任务列表完整恢复、下载中任务回「等待中」排队、获槽后从断点续传（已下载块不重传），最终完成且文件字节完整。 |
| AC-3 | fixture 模拟 5xx / 断连：任务转「已失败」并显示原因与倒计时；自动重试按 8→16→32→60s 退避；连续无进展失败计数累加至 5/5 达上限、释放槽位、显示「已达上限」；有进展的失败重置为 1；`R` 手动重试重置为 1 并重新排队。 |
| AC-4 | fixture 关闭 Range 支持：自动单并发下载、详情显示「不支持断点续传」；暂停后继续从头下载。 |
| AC-5 | 同时添加 7 个任务：槽位显示 5/5，第 6 / 7 个显示排队位次；暂停队首下载任务 → 队首等待任务递补；`U`/`J` 调整后递补顺序随之改变；「等待中」任务按 `Space` 暂停并退出队列。 |
| AC-6 | 校验：预置内容正确的 `<file>.sha256` → 完成后显示「校验成功」；预置错误摘要 → 「已失败（SHA-256 校验失败）」，`R` 重试从头下载。 |
| AC-7 | 限速 `max_speed = 1 MB/s`：全局速度稳定在约 1 MB/s（±10%）。 |
| AC-8 | 代理：经本地 HTTP 代理 fixture 下载成功（配置文件与环境变量两种途径各验证一次）。 |
| AC-9 | `Q` 优雅退出 → 重启任务与历史完整；`kill -9` → 重启无元数据损坏；`Ctrl+C` 退出后终端无花屏。 |
| AC-10 | 质量门槛：`cargo build` / clippy 零警告；单元测试全通过；附带本地 fixture 服务器（可模拟：支持/不支持 Range、随机断连、5xx、慢速、`Content-Disposition`、ETag 变化、代理），QA 套件基于它自动化复跑 AC-1~9，不依赖外网。 |
